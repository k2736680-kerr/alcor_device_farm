# ADR-0003：确定方案是目标架构最高优先级基线

## 状态

已确定；涉及 Alcor 平台对象、接口、存储、前端和集成边界的部分由 ADR-0004 补充并优先解释。

## 背景

当前设备域需要在 Alcor 接口尚未开发时先行建设。如果只根据当前可运行条件设计，容易把阶段性的独立仓库、临时 Owner ID 或 DaFit 联调方式误写成最终架构，造成后续推倒重来。

## 决策

- `docs/reference/app_evaluation_device_farm_design.md` 原样保存，作为设备农场功能和内部运行链路的基线；
- `docs/02_architecture_alignment.md` 只负责把目标架构映射到当前实施阶段，不改变目标；
- 当前仓库只建设方案中缺失的设备域，Alcor 业务域延期而不复制；
- API、表、状态机、模块和部署设计必须能够映射回确定方案；
- 与确定方案冲突的代码不得以“已经实现”为理由保留，必须先停止扩展并纠偏；
- 确需改变最终架构时，必须获得需求方明确确认并同时更新方案、对齐表和 ADR。

## 后果

- 当前可以不等待 Alcor 接口完成，但不会把临时边界固化为最终边界；
- 开发评审有明确的逐项对照依据；
- 后续真机、Alcor Worker 和 Console 接入沿用同一 Device、Reservation、Session 和 Executor 抽象，不需要重新设计设备农场核心。
